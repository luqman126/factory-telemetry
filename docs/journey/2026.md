### [2026-09-26] - End-to-End Patroni HA Orchestration, DCS Consensus & Zero-Downtime Switchover

#### Focus
- Successfully executed automated end-to-end provisioning of the entire 3-node decoupled architecture across AWS infrastructure, custom AMIs, and Ansible roles.
- Resolved PostgreSQL bootstrap permission hurdles and DCS connectivity to achieve automated Patroni cluster leader election on `datalayer-1` and streaming replica bootstrap on `datalayer-2`.
- Stabilized Tailscale Bastion networking by converting `applayer-1` from an ephemeral node to a persistent node with a static Tailscale IP (`100.74.162.40`).
- Validated high-availability failover and zero-downtime leader switchover (`datalayer-1` -> `datalayer-2`) with zero replication lag on Timeline 4.
- Hardened inter-node security group rules and eliminated client endpoint advertise issues in etcd.

#### Key Decisions & Architecture
- **Decoupled Consensus vs. Storage Quorum (2-Node DB + External DCS)**: Addressed why the database tier requires only two nodes (`datalayer-1` and `datalayer-2`) while etcd operates on Raft quorum. Because leader election and split-brain fencing are offloaded to atomic lease locks in `etcd`, the database layer achieves 100% split-brain immunity without incurring the compute and EBS storage costs of a redundant third database node.
- **Synchronous REST Handshake vs. Asynchronous DCS Fallback**: Identified why Patroni prefers direct REST API communication (`POST http://leader:8008/switchover`) during planned switchovers (graceful WAL flush, LSN verification, and zero-lag handoff) while maintaining etcd as the asynchronous fail-safe for unannounced node crashes.
- **Persistent vs. Ephemeral Node Lifecycles**: Diagnosed that ephemeral Tailscale auth keys cause nodes to be purged from the tailnet upon disconnection, leading to IP reassignments on reboot. Converted the bastion host to a persistent, reusable auth key, guaranteeing deterministic Ansible SSH ProxyCommand routing.
- **Secret Hygiene & Variable Precedence**: Enforced dynamic secret injection (`POSTGRES_PASSWORD`) via AWS SSM Parameter Store and `--extra-vars` in `run-ansible.sh`, removing hardcoded placeholder passwords from Ansible role defaults in accordance with CWE-798 best practices.

#### Challenges & Resolutions
- **Issue**: Task `Grant all privileges on database to user` failed with `cannot execute GRANT in a read-only transaction`.
  - **Root Cause**: `timescaledb_primary` did not assign a password to the `postgres` superuser. When Patroni started, it was rejected with password authentication errors, causing it to demote PostgreSQL and create `/var/lib/pgsql/data/standby.signal`. Native PostgreSQL then started in recovery (read-only) mode.
  - **Fix**: Added superuser password provisioning in `timescaledb_primary/tasks/configure.yml`, cleared `standby.signal`, wiped orphaned etcd initialize keys, and restarted the primary.
- **Issue**: `patronictl` printed connection refused warnings against `http://127.0.0.1:2379/v3/kv/range` on remote nodes.
  - **Root Cause**: `etcd` on `applayer-1` advertised both `10.1.1.10:2379` and `127.0.0.1:2379`. Remote datalayer nodes attempted to query their own local loopback for etcd before failing over to the VPC address.
  - **Fix**: Restricted `etcd_advertise_client_urls` to `http://{{ ansible_default_ipv4.address }}:2379` in `roles/etcd/defaults/main.yml`.
- **Issue**: `patronictl switchover` timed out calling `http://10.1.2.10:8008/switchover`.
  - **Root Cause**: Ingress on port 8008 was only permitted from `applayer-sg` (HAProxy), blocking direct REST API requests between datalayer nodes.
  - **Fix**: Added `aws_security_group_rule.datalayer_self_patroni` in `infra/terraform/security.tf` to permit port 8008 within `datalayer-sg`.
- **Issue**: `patronictl switchover` reported `Member 10.1.2.10 is not the leader`.
  - **Root Cause**: The prompt was supplied an IP address instead of the Patroni member name (`datalayer-1`).
  - **Fix**: Verified prompt defaults (pressing `<Enter>` accepts the bracketed member name default).

### [2026-09-16] - etcd Quorum Architecture, HAProxy L4 Routing & Security Groups

#### Focus
- Implemented Ansible automation for `etcd` and `haproxy` roles on `applayer`.
- Configured HAProxy Layer 4 TCP routing with Patroni REST health checks for PostgreSQL High Availability.
- Defined AWS Security Group rules in Terraform for etcd client traffic and Patroni health probes.
- Integrated `etcd` and `haproxy` roles into `ansible/site.yml`.

#### Key Decisions & Architecture
- **DCS vs. Database Quorum**: Confirmed that consensus quorum applies strictly to the etcd layer (Raft consensus) rather than PostgreSQL nodes, enabling a 2-node PostgreSQL cluster (Primary + Standby) with zero split-brain risk.
- **Layer 4 TCP Routing with Layer 7 Health Probes**: Configured HAProxy in `mode tcp` on port 5000 (Primary RW) and port 5001 (Standby RO), while health-checking Patroni's HTTP endpoints (`/primary` and `/replica`) on port 8008.
- **Failover Connection Fencing**: Applied `on-marked-down shutdown-sessions` in HAProxy to immediately terminate active client TCP connections when a node is demoted, forcing clients to reconnect to the new primary instantly.
- **Compaction Strategy**: Set `auto-compaction-retention: '1'` in etcd to hourly purge revision history older than 1 hour, preventing MVCC storage quota exhaustion from frequent Patroni lease heartbeats.
- **Ansible Role Modularity**: Structured roles with `import_tasks` (`install.yml`, `configure.yml`) and handlers for idempotent, deduplicated service restarts.

#### Challenges & Resolutions
- **Issue**: Ambiguity regarding Patroni REST API HTTP response codes on failover.
- **Root Cause & Fix**: Verified that `/primary` returns HTTP 200 only for the active leader (and 503 for standbys), while `/replica` returns HTTP 200 only for active standbys (and 503 for the leader).
- **Issue**: Network isolation between application and database security groups.
- **Root Cause & Fix**: Added explicit ingress rules in `infra/terraform/security.tf`: port 2379 into `applayer` SG from `datalayer` SG (etcd DCS client), and port 8008 into `datalayer` SG from `applayer` SG (Patroni health checks).
